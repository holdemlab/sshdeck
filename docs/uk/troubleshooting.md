# Проблеми та повідомлення

Помилки підключення показуються червоним у вкладці та в статус-рядку. Вкладка
лишається відкритою, і `r` перепідключає.

## Підключення

| Повідомлення | Що означає | Що робити |
|---|---|---|
| `dial tcp …: connect: connection refused` | на цьому порту нічого не слухає | перевір host і port сесії; чи запущений sshd |
| `dial tcp …: i/o timeout` / `context deadline exceeded` | хост не відповідає за `connect_timeout` | мережа, фаєрвол, VPN; чи не потрібен jump |
| `dial tcp: lookup …: no such host` | ім'я не резолвиться | для хостів за jump вказуй адресу так, як її бачить jump-хост |
| `… administratively prohibited` / `open failed` на вузлі після jump | jump-хост не відкриває канал далі | на jump-хості вимкнено `AllowTcpForwarding`, або ціль недосяжна з нього |
| `автентифікація не вдалася (не підійшов жоден ключ чи пароль)` (англійською: `authentication failed (no key or password accepted)`) | сервер не прийняв жодного ключа чи пароля | перевір user, `identity`, чи доданий публічний ключ у `authorized_keys`; див. [authentication.md](authentication.md) |
| `забагато невдалих спроб: …` (англійською: `too many authentication failures: …`) | сервер здався раніше, ніж дійшло до потрібного ключа | задай `identity` сесії; або `use_agent: false`, або менше ключів в агенті й `identities`; див. [jump-hosts.md](jump-hosts.md#too-many-authentication-failures) |
| питає passphrase не для того ключа | у версіях до цього виправлення sshdeck відкривав усі ключі заздалегідь; тепер passphrase питається тільки для ключа, прийнятого сервером | онови sshdeck; рядок `Пробую ключ …` у вкладці показує, який ключ використано |
| `ключ сервера не підтверджено` (англійською: `host key verification failed`) | на питання про ключ відповіли не `yes` / `так` | перепідключись і відповідай `yes` або `так`, якщо відбиток правильний |
| `КЛЮЧ СЕРВЕРА … ЗМІНИВСЯ` (англійською: `HOST KEY FOR … HAS CHANGED`) | ключ сервера не збігається зі збереженим | якщо зміна очікувана, видали вказаний рядок із `known_hosts`; див. [known_hosts](authentication.md#ключ-сервера-змінився) |
| `jump loop through …` | сесії посилаються одна на одну через `jump` | виправ ланцюжок |
| `jump "…": bad port` / `empty host` | рядок jump записано неправильно | формат `[user@]host[:port]`, IPv6 у `[…]` |
| `Не вдалося використати ключ …` (англійською: `Cannot use key …`) | файл `identity` не знайдено, він пошкоджений або це зашифрований PEM без `.pub` | перевір шлях; для старого PEM поклади поруч `ключ.pub` або перекодуй: `ssh-keygen -p -f ключ` |
| `pty request: …` | сервер не дав терміналу | на сервері заборонено pty (`PermitTTY no`) або обмеження в `authorized_keys` |

## Паролі та встановлення ключа

| Повідомлення | Що означає | Що робити |
|---|---|---|
| `Запам'ятований пароль не підійшов.` (англійською: `Remembered password was rejected.`) | пароль на сервері змінили | введи новий; старий уже забуто |
| `спершу підключись: ключ встановлюється через відкрите з'єднання` (англійською: `connect first: the key is installed over the open connection`) | `ctrl+a k` у вкладці без з'єднання | спершу підключись (паролем), потім `ctrl+a k` |
| `не вдалося встановити ключ: …` (англійською: `installing the key failed: …`) | сервер не дав записати `~/.ssh/authorized_keys` | на сервері немає `sh`, домашній каталог тільки для читання, або заборонено виконання команд |
| `… уже існує` (англійською: `… already exists`) при створенні ключа | файл із такою назвою з'явився, поки був відкритий діалог | sshdeck ніколи не перезаписує ключі; закрий діалог і відкрий `ctrl+a k` знову, він запропонує вільну назву |
| після встановлення ключа все одно питає пароль | ключ не прописано в сесії, або сервер не читає `authorized_keys` | відповідай `y` на `Надалі використовувати … для …?`; перевір права на сервері: `~/.ssh` 700, `authorized_keys` 600, домашній каталог без запису для інших |

## Під час роботи

| Повідомлення | Що означає |
|---|---|
| `З'єднання з … закрито.` (англійською: `Connection to … closed.`) | shell на сервері завершився (`exit`) |
| `віддалена програма завершилася з кодом N` (англійською: `remote exited with status N`) | команда чи shell завершилися з кодом N |
| `з'єднання втрачено` (англійською: `connection lost`) | зв'язок обірвався або сервер перестав відповідати на keepalive |

## Конфіги

| Ситуація | Що відбувається |
|---|---|
| помилка в `sessions.yaml` при запуску | sshdeck не стартує і пише, в якому рядку помилка |
| помилка в `sessions.yaml` після `E` або `r` | лишається попередній стан, у статус-рядку повідомлення з рядком помилки |
| помилка в `config.yaml` при запуску | старт зі значеннями за замовчуванням і повідомлення; виправити через `ctrl+a ,` |
| помилка в `config.yaml` після редагування | лишаються попередні налаштування, у статус-рядку повідомлення |
| зникли коментарі в `sessions.yaml` | файл перезаписується при змінах через UI; див. [sessions.md](sessions.md#ручне-редагування) |

## Клавіші

| Ситуація | Причина і рішення |
|---|---|
| `n`, `e`, `d` не реагують | фокус у терміналі, тож клавіші пішли на сервер; `ctrl+a s` переводить фокус на сайдбар |
| `ctrl+a` не доходить до tmux або bash на сервері | його забирає sshdeck; натисни двічі або зміни prefix ([settings.md](settings.md#prefix-і-tmux)) |
| sshdeck не реагує на prefix | sshdeck запущено всередині tmux із тим самим prefix; зміни prefix |
| `esc`, а потім швидко інша клавіша, спрацювали як `alt+…` | так термінали кодують alt; між `esc` і наступною клавішею треба коротка пауза |
