# Сесії й папки

Сесії зберігаються в `~/.config/sshdeck/sessions.yaml` у вигляді дерева: папки
містять сесії та інші папки. Редагувати дерево можна в sshdeck (див.
[нижче](#редагування-в-sshdeck)) або вручну у файлі.

## Формат файлу

```yaml
# корінь: налаштування для всіх сесій
user: admin

folders:
  - name: infra
    sessions:
      - name: proxy
        host: proxy.example.com
        user: jumper
        identity: ~/.ssh/id_proxy

  - name: prod
    jump: infra/proxy          # усе в prod іде через proxy
    identity: ~/.ssh/id_prod
    folders:
      - name: web
        user: deploy
        sessions:
          - name: web-01
            host: 10.0.10.11
            note: nginx + app
    sessions:
      - name: db-main
        host: 10.0.20.5
        port: 2222
        forwards:
          - L 5432:localhost:5432
      - name: db-top
        host: 10.0.20.5
        port: 2222
        command: htop

sessions:
  - name: homelab
    host: 192.168.1.10
    user: me
```

Повніший приклад: [`examples/sessions.yaml`](../../examples/sessions.yaml).

### Поля сесії

| Поле | Обов'язкове | Що означає |
|---|---|---|
| `name` | так | назва в дереві; унікальна в межах папки; без `/` |
| `host` | так | ім'я хоста або IP |
| `user` | ні | користувач; якщо порожньо, береться з папки або кореня, а якщо ніде не задано, то локальний `$USER` |
| `port` | ні | порт; за замовчуванням успадковується, інакше 22 |
| `jump` | ні | через що підключатися, див. [jump-hosts.md](jump-hosts.md) |
| `identity` | ні | шлях до приватного ключа, `~` розгортається; див. [authentication.md](authentication.md) |
| `command` | ні | команда замість login shell (як `ssh host command`), наприклад `htop` |
| `forwards` | ні | тунелі, які стартують разом із з'єднанням, див. [tunnels.md](tunnels.md) |
| `color` | ні | колір тексту в дереві й на вкладці, див. [кольорові позначки](#кольорові-позначки) |
| `fill` | ні | колір заливки (фону) в дереві й на вкладці |
| `note` | ні | довільна примітка; показується внизу сайдбару |

### Поля папки

| Поле | Що означає |
|---|---|
| `name` | назва; унікальна серед папок одного рівня |
| `user`, `port`, `jump`, `identity` | значення за замовчуванням для всього всередині |
| `color`, `fill` | кольорова позначка папки і всього всередині |
| `folders` | вкладені папки |
| `sessions` | сесії в цій папці |

Корінь файлу теж може мати `user`, `port`, `jump`, `identity`. Вони діють на всі
сесії.

## Успадкування

`user`, `port`, `jump` та `identity` шукаються від сесії вгору по дереву:
**сесія → її папка → батьківська папка → … → корінь**. Перемагає найближче
непорожнє значення.

Для `prod/web/web-01` з прикладу вище:

| Поле | Значення | Звідки |
|---|---|---|
| user | `deploy` | папка `prod/web` |
| port | 22 | ніде не задано |
| jump | `infra/proxy` | папка `prod` |
| identity | `~/.ssh/id_prod` | папка `prod` |

Що з цього вийшло, видно в сайдбарі під деревом: `user@host`, `через …`. У формі
редагування успадковане значення показується як `порожньо = успадкувати`.

Обмеження: успадковане значення можна тільки перевизначити іншим, «стерти» його
для однієї сесії не можна. Якщо в корені задано `jump`, а одна сесія має йти
напряму, тримай її в окремій гілці, де `jump` не задано.

## Кольорові позначки

Папку чи сесію можна позначити кольором, щоб середовища розрізнялися з першого
погляду: наприклад, `prod` червоною заливкою, `staging` помаранчевим текстом.

```yaml
folders:
  - name: prod
    fill: red          # заливка: усе в prod — на червоному фоні
    sessions:
      - {name: web-01, host: 10.0.0.1}
      - {name: lab, host: 10.0.0.9, fill: none}   # без заливки
  - name: staging
    color: peach       # колір тексту
```

| Поле | Що задає |
|---|---|
| `color` | колір тексту назви |
| `fill` | заливку (фон) назви; текст тоді автоматично темний або світлий, щоб читався. Колір тексту можна задати окремо |

**Значення:**
- назва з палітри Catppuccin: `rosewater`, `flamingo`, `pink`, `mauve`, `red`,
  `maroon`, `peach`, `yellow`, `green`, `teal`, `sky`, `sapphire`, `blue`,
  `lavender`, а також нейтральні `text`, `subtext`, `overlay`, `surface`.
  Також приймаються синоніми `orange`, `purple`, `cyan`, `gray`, `white`, `magenta`;
- `#rrggbb` або `#rgb` — будь-який колір;
- `none` — без кольору, навіть якщо папка вище має позначку;
- порожньо — успадкувати від папки.

Назви з палітри малюються кольорами **вибраної теми**: `red` у Mocha — це
червоний Mocha, у Latte — червоний Latte. З темою `terminal` береться палітра
Mocha для темного термінала і Latte для світлого. Колір `#rrggbb` завжди той самий.

**Успадкування** таке саме, як у `user` чи `jump`: позначка папки діє на всі
вкладені папки й сесії, поки хтось нижче не задасть свою (або `none`).

**Де видно:**
- у дереві: назва папки чи сесії; із заливкою вона виглядає як кольорова мітка;
- на вкладці: вкладка з'єднання малюється кольорами сесії. Якщо задано лише
  колір тексту, активна вкладка заливається ним. Активна вкладка завжди
  жирна й підкреслена;
- зміна кольорів одразу видна на відкритих вкладках.

**Як задати:**
- `C` у дереві відкриває вибір кольорів для вибраної папки чи сесії:
  ```
  Кольори prod/web

  ▸ Текст     ↑ ∅ ████████████████████████████████████  успадкувати
              ▔▔
    Заливка   ↑ ∅ ████████████████████████████████████  red
                      ▔▔
  Вигляд:  web
  ```
  `← →` вибирає колір, `↑↓` перемикає текст / заливку, `x` повертає
  «успадкувати», `enter` зберігає, `esc` скасовує. `↑` на смужці означає
  «успадкувати», `∅` — `none`. Під смужкою видно, як виглядатиме назва;
- у формі сесії чи папки (`e`, `n`) є поля **Колір** і **Заливка**: `← →`
  вибирає з палітри, або впиши `#rrggbb`. Під полями — попередній вигляд;
- вручну в `sessions.yaml`.

## Редагування в sshdeck

Усі дії працюють у сайдбарі. Якщо фокус у терміналі, спершу натисни `ctrl+a s`.

### Папки

- **`N`** відкриває рядок для назви прямо в дереві, у вибраній папці або поруч із
  вибраною сесією. Куди саме, видно в статус-рядку (`Нова папка в prod/web`).
  `a/b/c` створює всі рівні одразу.
  **`/` на початку означає верхній рівень**, де б не стояв курсор: `/infra`
  створить папку в корені, `/infra/dev` — `infra` в корені і `dev` у ній. `enter` створює, `esc`
  скасовує (якщо вже щось введено, спершу спитає). Якщо така папка вже є, рядок лишається відкритим із помилкою.
- **`R`** перейменовує прямо в рядку.
- **`e` на папці** відкриває форму:
  - Назва;
  - Всередині — батьківська папка; так папку можна перемістити, порожньо означає
    верхній рівень;
  - Користувач, Порт, Jump, Файл ключа — успадковуються всім усередині.
- **`d`** видаляє папку разом з усім вмістом. Перед видаленням діалог покаже
  кількість сесій усередині і попередить, якщо якісь із них використовуються як
  jump-хости.

### Сесії

- **`n`** створює нову сесію у вибраній папці: поле «Папка» заповнюється само.
  Порожнє поле «Папка» означає верхній рівень. Якщо вписати в «Папка» папку, якої
  ще немає, вона буде створена.
- **`e`** відкриває форму редагування з усіма полями; `ctrl+s` зберігає, `esc`
  скасовує. Якщо щось уже змінено, `esc` спершу спитає, чи викинути зміни (див.
  [keys.md](keys.md#захист-від-випадкового-esc)). Поле «Тунелі» приймає записи через кому: `L 8080:localhost:80, D 1080`.
- **`ctrl+a e`** редагує сесію поточної вкладки, коли фокус у терміналі.
- **`c`** робить копію поруч: відкривається форма з тими самими полями і
  вільною назвою (`…-copy`), щоб одразу поміняти host. Детальніше в розділі
  [Копіювання](#копіювання).
- **`R`** перейменовує прямо в рядку.
- **`d`** видаляє (з підтвердженням).

### Переміщення

- **`x`** вирізає сесію або папку (вона позначається `✂`).
- **`p`** вставляє у вибрану папку. Якщо курсор на сесії, то в папку цієї сесії.
- **`P`** вставляє на верхній рівень.
- **`esc`** скасовує переміщення.

Вкласти папку саму в себе не можна. Переміщена папка зберігає свої налаштування.
Стара папка, навіть порожня, лишається, і її можна видалити через `d`.

### Копіювання

Копіювати можна і сесії, і папки з усім вмістом.

- **`c`** дублює вибране поруч з оригіналом:
  - **сесія**: відкривається форма копії, яку можна підправити перед
    збереженням (`esc` нічого не створює);
  - **папка**: копія створюється одразу з назвою `…-copy`, і відкривається
    перейменування в рядку (`enter` лишає назву як є).
- **`y`**, потім **`p`** копіює в іншу папку (як `x`/`p`, тільки оригінал
  лишається на місці):
  - `y` позначає сесію або папку (`⧉`);
  - `p` вставляє копію у вибрану папку (якщо курсор на сесії, то в її папку);
  - `P` вставляє на верхній рівень;
  - `p` можна натискати кілька разів, щоб зробити кілька копій;
  - `esc` завершує копіювання.

Правила:
- **Назви.** Якщо в цільовій папці назва вже зайнята, додається `-copy`, далі
  `-copy-2`, `-copy-3`… У чужу папку копія потрапляє з тією ж назвою, якщо там
  вона вільна.
- **Копіюється все:** host, user, port, key, command, tunnels, note, налаштування
  папок і всі вкладені папки. Копія повністю незалежна від оригіналу.
- **Jump усередині скопійованої папки переводиться на копію.** Якщо в
  `acme/dev` сесія `main` ходить через `acme/dev/proxy`, то в копії
  `acme/stage` її `main` ходитиме через `acme/stage/proxy`. Так копія
  середовища одразу самодостатня. Посилання на сесії поза скопійованою папкою
  (наприклад, на спільний bastion) не змінюються.
- Копіювати папку всередину неї самої можна: копіюється стан на момент вставки,
  без нескінченної вкладеності.

### Що оновлюється автоматично

- Коли сесію чи папку перейменовують або переміщують, усі посилання `jump:` на
  неї (і на сесії всередині папки) переписуються на новий шлях.
- Відкриті вкладки отримують нові налаштування своєї сесії. Вони застосуються
  при наступному перепідключенні (`ctrl+a r`), а поточне з'єднання не
  переривається.
- Видалення сесії не закриває її відкриті вкладки.

### Згортання папок

- **Окремі папки:** `←` / `h` згортає папку (або переходить до батьківської),
  `→` / `l` розгортає, `enter` на папці перемикає.
- **Усі разом:** `H` або `-` згортає всі папки, включно з вкладеними. Курсор
  переходить на папку верхнього рівня, в якій він був. `L` або `*` розгортає
  всі.
- **Стан запам'ятовується між запусками**: які папки згорнуті, sshdeck
  відновить при наступному старті. Він зберігається не в `sessions.yaml`, а в
  окремому файлі стану `~/.local/state/sshdeck/state.yaml` (або
  `$XDG_STATE_HOME/sshdeck/state.yaml`). Файл можна видалити будь-коли: тоді все
  буде розгорнуте.
- **Стан іде за папкою:** після перейменування чи переміщення папка лишається
  згорнутою; копія папки згорнута так само, як оригінал; видалені папки з файлу
  стану прибираються.
- Під час пошуку дерево плоске, а згортання знову діє, щойно пошук скинуто.

### Пошук

`/` шукає за назвою, шляхом і хостом (нечіткий пошук: `pw1` знайде
`prod/web/web-01`). Під час пошуку дерево стає плоским списком. `enter` відкриває
сесію, `esc` скидає пошук.

## Ручне редагування

- **`E`** у сайдбарі відкриває `sessions.yaml` у `$VISUAL` або `$EDITOR` (за
  замовчуванням `vi`). Після виходу файл перевіряється і перечитується. Якщо в
  ньому помилка, sshdeck лишає попередній стан і показує помилку з номером рядка.
- **`r`** у сайдбарі перечитує файл, якщо він змінився ззовні.

Що перевіряється при завантаженні:
- у кожної сесії є `name` і `host`;
- назви не повторюються в межах однієї папки;
- кожен запис у `forwards` записаний правильно.

> Коли сесії змінюють через UI, файл перезаписується повністю, і **коментарі в
> `sessions.yaml` зникають**. Якщо коментарі важливі, редагуй файл тільки
> вручну (`E`).
