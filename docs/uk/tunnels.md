# Тунелі (port forwarding)

Тунелі прокидають порти через SSH-з'єднання. Наприклад, база або вебпанель, яку
видно тільки з сервера, стає доступною на `localhost` твоєї машини. Тунелі
працюють і через [jump-хости](jump-hosts.md): вони завжди йдуть через
з'єднання з **цільовим** сервером.

## Типи і формат

Запис такий самий, як у `ssh -L/-R/-D`:

```
L [bind:]port:host:hostport     локальний порт → host:hostport, видимий із сервера
D [bind:]port                   SOCKS-проксі: з'єднання виходять із сервера
R [bind:]port:host:hostport     порт на сервері → host:hostport, видимий з твоєї машини
```

| Приклад | Що відбувається |
|---|---|
| `L 5432:localhost:5432` | `127.0.0.1:5432` у тебе → порт 5432 **на самому сервері** |
| `L 9090:grafana.internal:3000` | `127.0.0.1:9090` у тебе → `grafana.internal:3000`, ім'я резолвить сервер |
| `L *:8080:web:80` | те саме, але слухає на всіх інтерфейсах твоєї машини |
| `L 0:db:5432` | вільний випадковий порт; який саме, видно в панелі тунелів |
| `D 1080` | SOCKS5 і SOCKS4a на `127.0.0.1:1080` |
| `R 9000:localhost:3000` | порт 9000 на сервері → `localhost:3000` у тебе |

Правила:
- адреса прив'язки за замовчуванням `127.0.0.1`: порт доступний тільки з твоєї
  машини; `localhost` теж означає `127.0.0.1`;
- `*` або `0.0.0.0` відкриває порт на всіх інтерфейсах. Обережно: тоді тунелем
  можуть скористатися інші машини в мережі;
- IPv6-адреси пишуться в дужках: `L 8080:[2001:db8::1]:443`;
- літеру можна писати маленькою і без пробілу (`l8080:…`); якщо літери немає,
  мається на увазі `L`.

### SOCKS (`D`)

- Підтримуються SOCKS5 (без авторизації, команда CONNECT) і SOCKS4/4a.
- Імена хостів резолвить сервер, якщо клієнт передає ім'я, а не IP. Приклади:
  `curl --socks5-hostname 127.0.0.1:1080 http://internal/`, або в браузері
  проксі SOCKS5 з опцією «DNS через проксі».
- Якщо задано змінну `no_proxy` / `NO_PROXY` (наприклад, `localhost`), curl і
  багато інших програм оминають проксі для цих адрес. Тоді запит до `localhost`
  через `D` піде повз тунель.

### Зворотні тунелі (`R`)

- Порт відкриває сам сервер.
- Чи можна прив'язатися до не-localhost адреси на сервері, вирішує його
  налаштування `GatewayPorts` у sshd.
- Порт 0 означає, що сервер вибере вільний порт; фактичну адресу видно в панелі.

## Тунелі в сесії (автостарт)

```yaml
- name: db-main
  host: 10.0.20.5
  forwards:
    - L 5432:localhost:5432
    - L 9090:grafana.internal:3000
    - D 1080
```

Або в UI: поле **Тунелі** у формі сесії (`e`), записи через кому.

Такі тунелі:
- піднімаються, щойно з'єднання встановлено;
- зупиняються, коли воно обривається;
- знову піднімаються після перепідключення (`r`).

Неправильно записаний тунель не дасть зберегти сесію: форма покаже помилку, а
файл не завантажиться з повідомленням, у якій сесії проблема.

## Режим «тільки тунелі»

`t` у сайдбарі відкриває сесію **без shell**: вкладка `⇄ db-main` лише тримає
з'єднання для тунелів. У ній видно журнал подій з часом:

```
Підключено. Тільки тунелі, без shell.
19:02:11 L 5432:localhost:5432 listening on 127.0.0.1:5432
19:02:40 L 9090:grafana.internal:3000: cannot reach grafana.internal:3000: …
```

Це зручно, коли потрібна тільки база чи вебпанель. `command` сесії в цьому
режимі не виконується.

## Панель тунелів: `ctrl+a t`

Показує тунелі поточної вкладки (будь-якої, звичайної чи `⇄`):

```
╭──────────────────────────────────────────────────────────────────────────────────╮
│  Тунелі — web-01                                                                 │
│  через jumper@proxy → deploy@web-01                                              │
│                                                                                  │
│  ● L  127.0.0.1:18080 → localhost:8099                                           │
│        відкрито 0 · усього 1 · 288 B                                             │
│  ○ D  127.0.0.1:11080 (SOCKS5)  (не збережено)                                   │
│        вимк.                                                                     │
│  ✗ L  127.0.0.1:5432 → localhost:5432                                            │
│        bind: address already in use                                              │
│                                                                                  │
│  пробіл увімк./вимк. · a додати · x видалити · w зберегти в сесію · esc закрити  │
╰──────────────────────────────────────────────────────────────────────────────────╯
```

Позначки:
- `●` — працює;
- `○` — вимкнено або чекає на з'єднання;
- `✗` — помилка (причина в рядку нижче).

Статистика в рядку під тунелем: відкриті з'єднання зараз, усього з'єднань,
передано байтів. Оновлюється щосекунди.

| Клавіша | Дія |
|---|---|
| `↑↓` `j k` | вибір |
| `space` / `enter` | увімкнути / вимкнути |
| `a` | додати тунель (рядок унизу; `enter` додати, `esc` скасувати; якщо вже щось введено, `esc` спершу спитає) |
| `x` | видалити зі вкладки |
| `w` | зберегти поточний набір тунелів у сесію (`forwards` у sessions.yaml) |
| `esc` / `q` / `t` | закрити панель |

**Збереження.**
- Тунелі, додані через `a`, позначені `(не збережено)`: вони живуть, поки відкрита
  вкладка.
- `w` записує в сесію всі тунелі вкладки, і вони стартуватимуть автоматично.
- Стан «вимкнено» не зберігається: після `w` при наступному підключенні
  стартують усі тунелі.

**Індикатори.** Кількість активних тунелів видно в таб-барі (`web-01 ⇄2`) і в
статус-рядку (`⇄ тунелів: 2`). Помилки тунелів звичайної вкладки
показуються в статус-рядку, щоб не засмічувати термінал.

## Типові помилки

| Повідомлення | Причина |
|---|---|
| `bind: address already in use` | локальний порт уже зайнятий: інший тунель, інша вкладка або програма |
| `bind: permission denied` | порт < 1024 на Linux потребує root; візьми порт ≥ 1024 |
| `cannot reach host:port: … connect failed` | сервер не може дістатися до цілі: не той хост або порт, або фаєрвол |
| `listener closed` (у `R`) | з'єднання з сервером обірвалося |
| сервер відмовляє в `R` | заборонено на сервері (`AllowTcpForwarding`, `GatewayPorts`) |
